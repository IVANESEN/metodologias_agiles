# ADR 0002 · PostgreSQL alojado en Supabase

Estado: Aceptada · 20 de octubre de 2026

## Contexto

Nuestra aplicación guarda contratos, máquinas, pagos y usuarios, y necesita transacciones: dos personas no pueden reservar la misma máquina en fechas que se cruzan, y un contrato con varias máquinas se guarda completo o no se guarda. Desde el Sprint 0 (7 de octubre) usamos PostgreSQL, y el `render.yaml` creaba una base gratuita de Render. Según Render, esas bases gratuitas expiran a los 30 días y, pasado un periodo de gracia, se borran con sus datos. Entre el 14 y el 16 de octubre pasamos a Supabase. Lo registramos hoy, días después de decidirlo.

## Decisión

Usaremos PostgreSQL en Supabase como base de producción, con la conexión cifrada y verificada. Descartamos la base gratuita de Render, porque expira, y guardar los datos en archivos del servidor (PGlite), porque en Render se pierden en cada despliegue. PGlite lo seguimos usando solo para desarrollar y probar.

## Consecuencias

+ Los datos viven fuera del servidor de Render: sobreviven a despliegues y reinicios, y no vencen a los 30 días.
+ Seguimos con PostgreSQL y sus transacciones, así que el cambio no tocó la lógica de las reservas.
- Dependemos de un segundo proveedor. Si el proyecto de Supabase está en el plan gratuito, se pausa después de 7 días con poca actividad y la aplicación deja de funcionar hasta restaurarlo.
- Conectarse se volvió más complicado: el archivo de conexión pasó de 76 a 243 líneas, y un dato mal copiado en `DATABASE_URL` impide que la aplicación arranque.
- Los cambios en las tablas no se aplican solos: hay que correr unos scripts a mano antes de publicar, y si se olvida, el servidor no arranca.
- Las pruebas corren sobre PGlite, que usa una sola conexión, así que no comprueban cómo se bloquean las reservas entre conexiones reales, y el pipeline no revisa la conexión con Supabase. Un fallo de red o de configuración solo aparece al desplegar.
- Cambiar de base no copia los datos viejos: lo que hubiera en la de Render no pasó a Supabase por sí solo.
