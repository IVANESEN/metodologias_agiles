# ADR-001: Uso de JavaScript, HTML, CSS y Node.js

- Estado: Aceptado
- Fecha: 20/10/2026
- Responsables: Todo el equipo

## Contexto

El equipo desarrolla un sistema de alquiler de maquinaria que permita consultar equipos, gestionar contratos y registrar pagos. El proyecto se desarrolla mediante sprints, priorizando la entrega incremental de valor al cliente.

Los desarrolladores tienen conocimientos previos de HTML, CSS y JavaScript. Se necesita aprovechar esa experiencia para implementar una interfaz web que se comunique con un backend conectado a PostgreSQL, dentro del tiempo disponible.

## Decisión

Se adopta una arquitectura cliente-servidor, utilizando:

- HTML: estructura y contenido de las páginas.
- CSS: presentación visual y adaptación a diferentes tamaños de pantalla.
- JavaScript: interacción del usuario, manipulación del DOM y comunicación con el backend.
- Node.js: ejecución del backend, procesamiento de solicitudes y aplicación de las reglas de negocio.

El frontend se comunicará con el backend mediante una API HTTP con intercambio de datos JSON. El backend accederá a PostgreSQL mediante la biblioteca pg, utilizando consultas parametrizadas.

Esta combinación permite utilizar JavaScript tanto en el frontend como en el backend y mantener una separación de responsabilidades entre presentación, interacción y acceso a datos.

## Consecuencias y sacrificios

- Se aprovechan los conocimientos del equipo y se concentra el esfuerzo en las historias de usuario.
- Se reduce la cantidad de lenguajes de programación que el equipo debe aprender y mantener.
- Se dispone de herramientas compatibles con PostgreSQL, las pruebas automatizadas y el despliegue en Render.
- Al utilizar JavaScript con tipado dinámico, se renuncia a la comprobación estática de tipos; algunos errores deberán detectarse mediante validaciones y pruebas.
- El equipo deberá programar y mantener las actualizaciones de la interfaz, como los mensajes, las listas y los totales, procurando reutilizar el código para evitar duplicaciones.
- Será necesario organizar el código en módulos para conservar la separación de responsabilidades y controlar la complejidad conforme crezca el sistema.
