# ADR-005: Aceptar temporalmente la preparación manual de PostgreSQL antes de publicar

Estado: Aceptada · 22 de octubre de 2026

## Contexto

En el taller de deuda técnica de la Sesión 23 (hallazgo 6) revisamos cómo se prepara la base de producción. Al arrancar, `backend/server.mjs` llama a `assertPostgresReady` (en `backend/postgres-preparation.mjs`), que comprueba que las tablas y columnas esperadas existan, pero no las crea ni las modifica. Los cambios de esquema se aplican antes de publicar, a mano, con `npm run db:inspect`, `npm run db:init` y `npm run db:verify`, como indica `DESPLIEGUE.md`. El ADR-002 ya reconoce que, si se olvida este paso, el servidor no arranca.

Automatizar las migraciones con control de versiones costaría unas 8 horas, incluida la validación de fallos y compatibilidad. Hoy esta deuda cobra poco interés: solo cobra en los despliegues que agregan tablas o restricciones, y eso ha pasado pocas veces.

## Decisión

Aceptamos esta deuda de forma temporal y no la incluimos en el Sprint 4. Mantendremos la preparación explícita del esquema y verificaremos la base con `npm run db:verify` antes de cada publicación que cambie tablas. Si los cambios de esquema se vuelven frecuentes, o si un despliegue falla por olvidar este paso, revisaremos esta decisión y planificaremos las migraciones automáticas.

## Consecuencias

+ Conservamos el control explícito sobre lo que se cambia en la base de producción: nada modifica tablas sin que alguien lo decida.
+ El servidor se niega a arrancar con un esquema incompleto, así que el error aparece al desplegar y no a mitad de una operación.
+ Las 8 horas que costaría automatizar quedan para la deuda que sí cobra intereses (DT-S4-01 a DT-S4-04).
- Seguimos dependiendo de que alguien recuerde preparar la base antes de publicar. Si se olvida, la aplicación queda caída hasta que se ejecuten los scripts.
- No hay un historial versionado de cambios de esquema; para saber qué se aplicó hay que revisar los scripts y la propia base.
- Cada nuevo cambio de esquema aumenta el costo de pagar esta deuda después.
