# ADR-004: Desplegar en Render mediante GitHub Actions después de aprobar las pruebas

Estado: Aceptado · 20 de octubre de 2026

## Contexto

El equipo integra cambios desde distintas ramas a main durante cada sprint. Necesitamos que la versión pública corresponda al código que aprobó las pruebas. Ya utilizamos GitHub y Render, y contamos con poco tiempo para administrar infraestructura.

## Decisión

Desplegaremos en Render desde GitHub Actions únicamente cuando un push a main apruebe las etapas build y test. Desactivaremos el auto-deploy de Render para publicar el commit probado y comprobar después el estado de la aplicación.

## Consecuencias

+ Bloqueamos el despliegue cuando fallan las verificaciones.
+ Registramos el commit probado y publicado en un mismo flujo.
+ Evitamos despliegues duplicados entre Render y GitHub Actions.
- La publicación tarda más porque espera las pruebas y el despliegue.
- Debemos mantener el pipeline y los secretos de acceso a Render.
- Si GitHub Actions o la API de Render fallan, no podemos publicar mediante este flujo aunque el código funcione.
- La restauración de una versión anterior sigue siendo manual.
